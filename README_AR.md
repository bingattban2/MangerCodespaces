# التمام اليومي — التحقق المستقل للخطوة 00.01

**هذه حزمة اختبار منفصلة، وليست جزءاً من برنامج التمام اليومي.** لم يجرِ تعديل أي ملف في مستودع `bingattban2/MangerCodespaces`.

## الاستخدام الموصى به عبر GitHub دون الحاجة إلى كمبيوتر Windows
1. أنشئ مستودع GitHub مستقلًّا للاختبارات فقط (يمكن أن يكون خاصًّا)، وليكن `AlTamam-External-Verification`.
2. ارفع محتويات **هذا المجلد** إلى جذر المستودع الجديد، بما فيها `.github/workflows/phase00-step01.yml` و`CSharpRunner` و`run_windows.ps1` (لا ترفع ZIP المصدر أو بيانات أشخاص).
3. افتح Actions في **مستودع الاختبارات المستقل**، ثم `AlTamam Phase 00 Step 01 External Windows Verification`، واضغط `Run workflow`.
4. بعد اكتمال التشغيل، حمل ملف artifact باسم `phase00-step01-windows-evidence` وأرسل نتائجه للمراجعة.

يعمل الإجراء على `windows-latest` مع .NET 10، ويجلب من المستودع العام **Commit محدداً وثابتاً**:
`200397747641b9553a733d9ba432a2d5b75f8ded`.
يتأكد السكربت من بصمته قبل البدء، ويجمع سجلات restore/build ونتائج C# وSQLCipher في مسار مستقل `evidence/` خارج مصدر الإنتاج.

**تنبيه:** هذه الحزمة مُعدّة للعمل، لكن لم تُشغّل على Windows في البيئة الحالية. أي فشل في تجميع الفاحص أو اختبار SQLCipher يبقى فشلاً صريحاً. لا يُعتمد اجتياز البوابة إلا بوجود سجلات نجاح فعلية. لا تختبر بكلمات مرور أو قواعد بيانات لأفراد حقيقيين.

## ما يشمله الفاحص
- اختبار قواعد الصلاحيات والتفويض، التواريخ وفترات المواقع، تحقق كلمات المرور، ونتيجة خريطة التتبع عبر C#.
- تشغيل SQLCipher الحقيقية مع إنشاء قاعدة جديدة مؤقتة، والتحقق من ترويسة الملف والتكامل، والحفظ بعد إعادة الفتح، والمفتاح الخاطئ والتراجع عند خطأ.
- يقوم فقط بفحص البنية الحالية، ولا يزعم تشغيل مضيف WebView2 أو خدمات أعمال لم تُنشأ بعد.
